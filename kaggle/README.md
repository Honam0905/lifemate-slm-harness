# Kaggle overnight ASR run (2 × T4)

Notebook: `kaggle/lifemate_asr_overnight.ipynb` (generated by `kaggle/make_notebook.py`; edit that file, then rerun it).

## 1. Two private datasets (Kaggle → Datasets → New Dataset → **Private**)

| Dataset | Upload | Needed inside |
|---|---|---|
| `lifemate-data` | the official folder (as downloaded) | `train/train.jsonl`, `train/audio/` (5,036 wav), `public_test/public_test.jsonl`, `public_test/audio/` (1,933 wav) |
| `lifemate-code` | `lifemate-code-kaggle.zip` (Kaggle unpacks it) | `lifemate/`, `scripts/`, `configs/`, `kaggle/`, `artifacts/splits/`, `artifacts/asr_ft/` |

Nesting doesn't matter: the notebook searches `/kaggle/input` for both. Competition data: keep it private and share it only with team members.
To change the code later, upload a new version of `lifemate-code` only (small); the data dataset stays.

## 2. Notebook
New Notebook → File → Import Notebook → `lifemate_asr_overnight.ipynb`. Right panel:
**Accelerator: GPU T4 ×2**, **Internet: On** (needs a phone-verified account), **Add Input**: both datasets.
Optional: Add-ons → Secrets → `HF_TOKEN` (only if Hugging Face rate-limits the 4.7 GB download).

## 3. Smoke test (interactive, ~10–15 min)
Leave `MODE = "smoke"`, Run All. Check in the output:
- `gpus: 2 ['Tesla T4', 'Tesla T4']` and torch unchanged (the install keeps Kaggle's CUDA torch)
- `[asr-ddp] 2 GPU(s) ... effective batch 16`, `supervised text of example 0` equals the manifest text + `<|im_end|>`
- `step 1/4 ... mem X.XG` — must stay below ~14.5 G (if out of memory: `GRAD_CKPT = True`)
- three dev examples printed (gold / base / A s4) and `SMOKE OK`

## 4. Overnight run
Set `MODE = "full"` → **Save Version** → *Save & Run All (Commit)* → close the tab.
Estimated 2–3 h on 2 × T4 (first run on this hardware, so a guess; Kaggle's limit is 12 h). Order:
Model A (200 steps) → dev transcripts base / A-s100 / A-s200 + WER → Model B (314 steps, all clips) → public transcripts with B-s157 and B-s314.

## 5. Next morning
Notebook → Versions → the latest → **Output** → download `out/` (or `kaggle kernels output <user>/<notebook> -p out`).

| In `out/` | What |
|---|---|
| `A/step100`, `A/step200` | LoRA adapters, train partition only (honest dev evaluation) |
| `B/step157`, `B/step314` | LoRA adapters on all clips (final-fit candidates; **never score on dev/audit**) |
| `asr/<cache name>/train.jsonl` | dev transcripts: `kgbase` (no fine-tune), `ftA-s100`, `ftA-s200` |
| `asr/<cache name>/public_test.jsonl` | public transcripts with `ftB-s157`, `ftB-s314` |
| `results.json`, `SUMMARY.md`, `logs/`, `pip_freeze.txt` | dev WER, holdout losses, timings, every log |

Then on Colab (agent decides, not WER):
```bash
cp -r out/asr/* artifacts/asr/
for t in kgbase ftA_s100 ftA_s200; do
  python -m lifemate.eval.run_eval --config configs/kaggle_${t}_names.yaml --name kg-$t \
      --model artifacts/models/v1-epoch2 --conditions C
done
python -m lifemate.eval.report artifacts/eval/kg-ftA_s100/dev.C/rows.jsonl --vs artifacts/eval/kg-kgbase/dev.C/rows.jsonl
```
Adopt the fine-tuned ASR only if the paired 95% interval is above 0. Then ship the matching Model B checkpoint
(A-s100 → B-s157, A-s200 → B-s314): merge it for Docker with
`python scripts/train_asr_lora.py merge --ckpt out/B/step314 --out artifacts/models/asr-ftB-s314`, and use
`out/asr/<ftB cache>/public_test.jsonl` with `infer/run.py --asr_cache` for a quick public submission.
